# 文章图片角色

在规划隐喻图之前，先判断文章已有图片在叙事中做什么。角色是图片与正文的关系，不是文件类型。

| 角色 | 它让读者看见什么 | 常见位置 |
| --- | --- | --- |
| 输入 | 作者给了模型、工具或流程什么 | 任务要求与难点之后 |
| 过程 | 一次关键操作、状态或中间产物 | 需要理解下一步为何发生的位置 |
| 结果 | 实际完成、可运行或可验证的东西 | 结果首次揭示的位置 |
| 失败 | 错位、崩溃、遗漏、异常或不满意之处 | 作者改变方案之前 |
| 对照 | 修改前后、版本差异或两种方案 | 文章要解释具体差异的位置 |
| 概念解释 | 现实截图难以表达的关系、机制或认知转折 | 读者理解存在断点的位置 |

## 决策顺序

1. 先列出现有图片及其角色，确认文章在关键动作和判断处有没有真实画面。
2. 结果、失败与对照图优先于概念解释图；它们承担的是证据与叙事，不能由凯冰插画替代。
3. 只有关系、机制或情绪转折仅靠文字和现有画面仍难理解时，才规划概念解释图。
4. 若移除拟新增插画，读者对正文的理解没有明显损失，输出“不需要新增正文隐喻图”。

## Shot List 增补字段

除既有字段外，记录：

- `image_role`: 必须为 `concept`；其他角色来自用户或文章素材，不由本 Skill 伪造；
- `narrative_job`: 这张图帮助读者跨过哪个理解断点；
- `existing_evidence`: 它附近已有的结果、过程或对照图；
- `omit_if`: 哪种已有素材到位后可以取消这张图。

不要为了让凯冰露脸而增加图片。角色身份的稳定由视觉规则保证，文章是否需要她出现由阅读任务决定。
